    1. Create `ZipWorker` in `services/gallery-service/src/services/zip_worker.py`:
       - Uses asyncio background task (not Celery — gallery-service has no Celery; use `asyncio.create_task` spawned from the endpoint). Per CONTEXT.md decision, this is server-side async ZIP.
       - `async def generate_zip(job_id: str, workspace_id: UUID, gallery_id: UUID, asset_list: List[dict], size: str, download_service: DownloadService)`:
         a. Set Redis key `download:job:{job_id}` = `{"status": "processing", "progress": 0}`
         b. For each asset: download/resize via DownloadService, add to in-memory ZIP buffer (use `zipfile.ZipFile` with `io.BytesIO`), update progress in Redis
         c. Upload completed ZIP to R2 at key `downloads/{workspace_id}/{gallery_id}/{job_id}.zip`
         d. Generate presigned URL (24h expiry) and update Redis: `{"status": "complete", "progress": 100, "download_url": "...", "expires_in": 86400}`
         e. On error: set Redis `{"status": "failed", "error": "..."}`
       - ZIP naming: `{gallery_name}_{size}_{YYYYMMDD}.zip`, files inside named by original filename or `photo_{index}.{ext}`
       - Memory guard: if total estimated size > 2GB, return error suggesting smaller batch

    2. Create public download endpoints in `services/gallery-service/src/api/v1/public/downloads.py`:
       - `POST /public/galleries/{token}/downloads/single` — validates magic link token, checks download_policy, calls DownloadService.get_or_create_resized(), tracks download, returns `{"download_url": "..."}`. Request body: SingleDownloadRequest.
       - `POST /public/galleries/{token}/downloads/batch` — validates magic link token, checks download_policy, spawns ZipWorker task via asyncio.create_task, returns `{"job_id": "..."}`. Request body: BatchDownloadRequest. If include_favorites or include_selections is true, query gallery_visitor_actions for the visitor_token to get asset_ids.
       - `GET /public/galleries/{token}/downloads/job/{job_id}` — reads Redis key, returns DownloadJobResponse.
       - `GET /public/galleries/{token}/downloads/job/{job_id}/stream` — SSE endpoint: polls Redis every 1s, yields `data: {json}\n\n` events until status is 'complete' or 'failed', then closes.
       - All endpoints extract workspace_id and gallery_id from validated magic link token — never from client params.

    3. Add authenticated download tracking endpoint to `services/gallery-service/src/api/v1/galleries.py`:
       - `GET /galleries/{gallery_id}/downloads/log?page=1&per_page=50` — calls DownloadService.get_download_log(), requires workspace auth. Returns DownloadTrackingResponse.

    4. Register the new public downloads router in `main.py` alongside existing public routers.

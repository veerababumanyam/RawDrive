       - `useSignedUrl` or URL generation that requires JWT tokens
       - Direct calls to authenticated API endpoints (not public endpoints)

       - If a hook calls `useSignedUrl(assetId)` internally, change it to accept `imageUrl: string` as a parameter

       - This makes the hook work with both JWT-authenticated signed URLs (workspace) and magic-link-token signed URLs (public)

    3. **Refactor navigation to accept asset list via parameter:**
       - If `useLightboxNavigation` reads assets from a workspace-specific context, change it to accept `assets: Array<{ id: string; url: string }>` as a parameter
       - Navigation logic (next/prev/goTo) remains the same, just decoupled from the data source

    4. **Refactor gesture handling:**
       - `useLightboxGestures` should accept callbacks (`onSwipeLeft`, `onSwipeRight`, `onPinchZoom`, `onDoubleTap`) rather than directly calling navigation functions from a specific context
       - This allows different callers to wire gestures to different actions

    5. **Preserve backward compatibility:**
       - The existing `Lightbox.tsx` component MUST continue to work without changes
       - If the hook signature changes, provide default parameters or a wrapper that maintains the old interface
       - Check that `LightboxContext.tsx` still provides the right data to `Lightbox.tsx`

    6. **Update `frontend/src/hooks/lightbox/index.ts`** to export all hooks (ensure no broken re-exports).

    NOTE: Do NOT touch `useLightboxSlideshow.ts` or `useLightboxCompare.ts` — these are workspace-only features and do not need decoupling for the public gallery player.

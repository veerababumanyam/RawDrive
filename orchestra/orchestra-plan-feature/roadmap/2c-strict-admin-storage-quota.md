# 2c - Use admin-defined storage quota in strict upload accounting

**Status:** PENDING

> Build with: `/orchestra-task-add 2c`

## User story

As an admin, when I define storage space for the free plan, free workspaces should be unable to upload beyond that exact quota until they upgrade to a paid subscription.

## Scope

- **Goal:** Make upload reservation and usage fallback read admin catalog quota bytes for the workspace plan and fail closed on quota lookup errors.
- **Summary:** Wire the plan catalog into storage accounting so missing/stale workspace_storage rows are seeded and displayed from subscription_plans.quota_bytes, not static PlanDefaultQuotaBytes, while preserving the existing atomic ReserveUpload quota check.
- **Out of scope:** Changing Backblaze B2 storage driver configuration
- **Out of scope:** Changing pay-per-event gallery-specific quota enforcement
- **Out of scope:** Allowing quota_bytes = 0 for free plans

## Acceptance criteria

- [ ] StorageAccounting.GetUsage falls back to the DB-backed plan catalog quota for the workspace plan when workspace_storage.quota_bytes is zero.
- [ ] StorageAccounting.ReserveUpload seeds missing workspace_storage rows from subscription_plans.quota_bytes instead of hardcoded static tier values when a DB catalog is wired.
- [ ] Upload reservation remains atomic and still includes used_bytes, derivative_bytes, reserved_bytes, and grace_bytes in the limit predicate.
- [ ] Quota lookup/storage errors on upload session creation return a retryable server error and do not allow uploads to proceed.
- [ ] Paid subscription settlement continues to update workspace_storage.quota_bytes to the paid catalog quota when payment is verified.

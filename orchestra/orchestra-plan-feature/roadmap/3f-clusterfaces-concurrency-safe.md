## User story

As a photographer, I want a single new person to be assigned one cluster even when the worker batch and a client ingest run concurrently, so the same face is not split into duplicate clusters the merge UI must repair.

## Scope

- **Goal:** Serialize/atomicize the no-match -> new-cluster decision so concurrent ingest cannot create duplicate clusters for the same person.
- **Summary:** ClusterFaces is a non-transactional read-then-uuid.New(): two faces of the same new person processed concurrently both see 'no cluster' and mint different labels. Make first-face cluster assignment concurrency-safe via an advisory lock / FOR UPDATE / dedupe-on-first-face so concurrent ingest converges on one cluster.
- **Out of scope:** Changing similarity thresholds (that is 3h)
- **Out of scope:** Changing the merge UI (it stays as the manual repair path)

- [ ] Alias resolution and the existing transactional merge path are unchanged.

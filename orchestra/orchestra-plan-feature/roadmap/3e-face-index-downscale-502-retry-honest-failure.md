## User story

As a photographer uploading to an E2EE gallery, I want face indexing to not silently fail when the frame is too large or the sidecar is unavailable, so Find-Me is not silently empty.

## Scope

- **Goal:** Eliminate the 413/502 silent no-index hazard on both the explicit index path and the upload-time path, and stop silently swallowing the 503.
- **Summary:** The in-browser index path POSTs the 2400px display_webp first and only retries smaller on a message matching 'too large'/'413', missing the documented nginx 502/body-reset; the upload path has no retry and swallows failures with console.warn. Proactively downscale the frame before the first POST, treat 502/body-reset as retryable with progressive downscale, and surface an honest 'indexing unavailable' signal instead of a silent no-index when the sidecar returns 503.
- **Out of scope:** Moving selfie embedding client-side (query path; part of the 2b/posture decision in 3j)
- **Out of scope:** Implementing in-browser ONNX embedding (owner-blocked, 3j)

## Acceptance criteria

- [ ] The face-index frame is downscaled below the 10MB server cap before the first POST (no longer sends the full 2400px display_webp blindly).
- [ ] A 502 / connection-reset / body-reset response is treated as retryable with progressive downscale, not just a message matching 'too large'/'413'.
- [ ] Upload-time face indexing no longer swallows failures as console.warn only: a 503/unavailable surfaces an honest 'indexing unavailable' signal to the caller/UI.
- [ ] Unit tests cover: pre-downscale chosen frame size, 502-retry path, and the honest-unavailable signal on 503.

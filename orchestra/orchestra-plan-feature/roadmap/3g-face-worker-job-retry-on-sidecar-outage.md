## User story

As an operator, I want a whole-batch face-sidecar outage to mark the scan job failed/retryable rather than done with faces_found:0, so transient downtime does not permanently complete an empty scan.

## Scope

- **Goal:** Distinguish a real empty result from a sidecar outage and set job state to failed/retry on outage.
- **Summary:** Per-asset sidecar errors are logged and the loop continues, then the job is marked done regardless; a whole-batch outage 'succeeds' with 0 faces and no retry. Detect a whole-batch sidecar-unavailable condition and mark the job failed/retryable (preserving the atomic claim + lease) instead of done.
- **Out of scope:** Changing the atomic claim query (it is already compliant)
- **Out of scope:** The E2EE server-detection dead path (B-E1, not the everyday path)

## Dependencies

- None (no upstream sub-feature)

## Acceptance criteria

- [ ] When the sidecar is unavailable for an entire batch (e.g. all asset calls return ErrServiceUnavailable/503), the job is marked failed/retryable, not done.
- [ ] A genuinely empty-but-healthy batch still completes done with faces_found:0.
- [ ] A unit test simulates a whole-batch sidecar outage and asserts the job ends failed/retryable; a healthy empty batch ends done.
- [ ] The atomic FOR UPDATE SKIP LOCKED claim + lease behavior is preserved.

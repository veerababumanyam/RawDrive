## User story

As a guest, I want one consistent, capable public Find-Me experience regardless of entry point, and an honest E2EE-unavailable state, so I do not hit a weaker modal that drops the honest state into dead code.

## Scope

- **Goal:** One capable public Find-Me path; the honest E2EE-unavailable state is reachable, not dead code; the encrypted prop is used.
- **Summary:** Two divergent public Find-Me UIs exist: the polished standalone page and the weaker modal faceid-gate (which lacks secure-context detection, the camera-error classifier, and the faces_detected===0 vs index_status==='empty' distinction, declares an honest 'unavailable' panel that is never reached because setStep('unavailable') is never called, and discards the encrypted prop). Converge the modal onto the stronger standalone implementation (or route the modal entry into the standalone flow) and wire or delete the dead unavailable branch so the encrypted/E2EE state is honest. Also fixes FE-5: replace the brittle regex-on-error-body feature-disabled detection with a typed status/structured signal so a backend copy change cannot break the friendly panel.
- **Out of scope:** Backend changes
- **Out of scope:** The capture-modal a11y fixes (that is 3l) unless the modal is deleted here

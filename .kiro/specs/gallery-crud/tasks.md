# Implementation Plan

## ⚠️ MAJOR ARCHITECTURAL REWORK REQUIRED

**Status**: All tasks marked incomplete for comprehensive rework

**Architectural Changes**:
- All media files encrypted with AES-256-GCM before storage
- WebP-only format for thumbnails and previews
- Time-limited signed URLs for all media access (1-hour TTL)
- Workspace-scoped encryption keys with rotation support
- Comprehensive audit logging for SOC2/GDPR compliance
- No direct R2 access - all media served through decryption proxy

**Technical Specs**:
- `docs/TechnicalSpecs/secure_media_handling.json` - Encryption and security
- `docs/TechnicalSpecs/galleries_client_portal.json` - Gallery data model
- `docs/TechnicalSpecs/storage_ingestion_byos.json` - Storage organization
- `docs/TechnicalSpecs/media_processing.json` - Image processing

**Process Flow (Photographer Workflow)**:
1. Photographer creates gallery/sub-gallery for client
2. Photographer uploads photos via drag-drop
3. Uploader extracts metadata (EXIF) and stores in database
4. Uploader generates encrypted WebP thumbnail (512px) → R2
5. Uploader generates encrypted WebP preview (2048px) → R2
6. Uploader encrypts and stores original → R2
7. Gallery fetches signed URLs and decrypts thumbnails for display
8. Click on thumbnail → decrypt and display WebP preview in lightbox
9. Download → prompt for WebP or original, serve decrypted file

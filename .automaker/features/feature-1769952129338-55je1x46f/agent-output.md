1. **State variables**: `loading`/`isLoading`, `error`, `data`, `isFetching`
2. **Mounted ref pattern**: `isMountedRef` to avoid setting state after unmount
3. **AbortController pattern**: for cancelling in-flight requests
4. **Refetch/refresh function**: wrapped in `useCallback`
5. **Auto-fetch on mount**: controlled by `enabled` or `autoFetch`
6. **Polling/refetch interval**: for stale-while-revalidate

I also notice that many hooks use React Query (`@tanstack/react-query`), which already handles much of this. However, there are still many custom hooks using raw state management. The `useAsyncData` hook should provide a cleaner abstraction for those cases.

## Summary: Extract shared async data fetching patterns into useAsyncData hook

### Changes Implemented
- Created a unified `useAsyncData<T>(asyncFn, options)` hook that consolidates duplicated async data fetching patterns from 50+ frontend hooks
- Implemented the following features:
  - **Loading states**: `idle | loading | success | error` with corresponding boolean helpers (`isLoading`, `isFetching`, `isSuccess`, `isError`, `isIdle`)
  - **Automatic error handling**: Converts non-Error exceptions to Error, provides onError/onSuccess/onSettled callbacks
  - **Configurable retries**: Exponential backoff with `retryCount`, `retryDelay`, and `maxRetryDelay` options
  - **Request cancellation**: AbortController integration, cancels in-flight requests on refetch/unmount
  - **Stale-while-revalidate**: `staleTime` and `keepPreviousData` options for caching patterns
  - **Polling/refetch intervals**: `refetchInterval` for automatic polling, `refetchOnWindowFocus` support
  - **Dependencies tracking**: `deps` array that triggers refetch when changed
  - **Optimistic updates**: `setData` function for optimistic UI updates
  - **Request deduplication**: `dedupe` option to prevent concurrent duplicate requests

- Created two utility hooks:
  - `useAsyncOnce`: Simplified version for one-time fetches (no retries/polling)
  - `useAsyncMutation`: For manual-trigger async operations (mutations)

- `frontend/src/hooks/useAsyncData.ts` (new file - 680 lines)
- `frontend/src/hooks/__tests__/useAsyncData.test.ts` (new file - 35 tests, all passing)
- `frontend/src/hooks/index.ts` (updated exports)

### Notes for Developer
- The hook is designed to be a drop-in replacement for the duplicated patterns found in `useActivities`, `useWebhookSubscriptions`, `useGallery`, `useStorageUsage`, and 47+ other hooks
- Full TypeScript support with comprehensive type exports
- AbortSignal is passed to the async function for proper request cancellation
- The hook uses React's `useMemo` to prevent unnecessary re-renders
- Migration path: Existing hooks can gradually adopt `useAsyncData` to reduce boilerplate while maintaining backward compatibility

// Basic usage

const { data, isFetching } = useAsyncData(
  (signal) => fetchStatus(signal),
  { retryCount: 3, refetchInterval: 5000 }
);

// With dependencies
const { data } = useAsyncData(
  (signal) => fetchGallery(galleryId, signal),
  { deps: [galleryId], enabled: !!galleryId }
);
